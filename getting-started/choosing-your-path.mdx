Adopt serves two roles, and you might be one or both. Use this to decide where to start.

## You're an End user if…

- Someone has already set up the agents you use.
- Your day-to-day is running a task, reviewing what it prepared, and approving or returning it.
- You think in terms of **clients, files, and finished work** — not tables, connectors, or scopes.

Start here: the [End user guide](/end-user-guide/running-a-task). The essentials are running a task, the review queue, and notifications.

## You're a Builder if…

- You set up agents: connect data sources, define what the agent does, choose its skills.
- You decide who can access which client and what an agent is allowed to read.
- You schedule and publish agents for others to use.

Start here: the [Builder guide](/builder-guide/builder-overview). Begin with connectors and data, then agents and skills.

## You're an Admin if…

- You manage members, roles, billing, and org-wide settings.
- You're responsible for security posture and usage reporting.

Start here: [Admin](/admin/managing-members) and [Security & access](/security-access/isolation-and-multi-tenancy).

## Everyone should read

Whatever your role, two things are worth ten minutes up front:

1. [The object model](/core-concepts/the-object-model) — the handful of concepts everything else is built on.
2. [Human-in-the-loop review](/core-concepts/human-in-the-loop) — how approval works, because it touches every role.
